## 1. 已确认的产品方向

- 产品定位：面向知乎平台创作者、盐言小说签约者和知乎故事创作者的宣发工作台，未来希望内嵌知乎。
- 品牌气质：专业、符合知乎调性，同时具有克制的陪伴感；专业可信是底座，角色温度是辅助。
- 卡通角色：既形成品牌辨识度，也作为创作搭档承担引导、等待、成功、失败和导出反馈。
- 视觉密度：贴近知乎创作者工具的中等密度，内容优先，完整成体系；避免过度留白和后台式拥挤。
- 保留内容：完整创作流程、作品结果、海报编辑能力。
- 优化重点：视觉层级、步骤状态、产品文案、等待反馈、不一致的卡片和按钮；模型名、内部指标、技术状态默认不进入主界面。
- 角色状态：首次进入/空状态、理解故事、设计分镜、生成画面、创作配乐、成功、失败和导出完成；编辑画布中仅在空状态或关键提示出现。
- 等待情绪：安静专注为主，高效明确为辅。
- 硬性禁区：廉价蓝紫 AI 渐变、大面积发光、过度玻璃拟态、儿童化玩具感、所有内容同构圆角卡片、角色喧宾夺主。

## 3. 知乎平台调研结论

调研优先使用知乎官方页面、知乎静态官方材料与投资者关系报告。

- 知乎创作者产品的核心不是“展示 AI”，而是支持内容创作、复盘与传播；界面应让作品和创作决策成为主体。
- 知乎长期使用高识别度蓝色作为行动、链接与选中信号，配合大面积白色和浅灰内容面；不应把整页染成蓝色。
- 官方材料强调创作者服务、内容质量和 AIGC 规范管理。产品语气需要突出事实复核、原作授权和创作者控制权。
- 创作者中心信息密度偏中等，列表、分组和明确文字操作比装饰性卡片更符合用户习惯。
- 设计策略：蓝色负责行动与定位，灰白负责阅读，角色及道具使用白、黑、蓝灰，状态色只承担语义。

## 4. 视觉参考分析

参考目录包含 3 张角色静态图与 6 个透明 GIF（待机、打招呼、晃悠、电脑、瞌睡、运球）。按用户最新要求复用提供的角色素材，并基于三视图补充创作姿态。

### 造型与比例

- 参考角色使用大躯干、小短肢、极简五官和一个夸张主特征，轮廓远看即可识别。
- 正侧背三视图保持几何体积一致，适合扩展成连续动画和多状态素材。
- 当前采用用户提供的刘看山：保留尖耳、白色连贯头身、大黑鼻、细黑四肢与白色短尾。第一版故事獭已弃用。

### 表情与动作语言

- 参考角色面部变化很少，情绪主要依靠重心、手臂、头部角度和道具表达。
- 动作具有清楚的准备—主动作—回位节奏；循环首尾衔接自然。
- 本项目沿用“低面部复杂度、强姿态和道具叙事”的方法：翻书=理解故事，整理卡片=设计分镜，落笔=生成画面，戴耳机=创作配乐。

### 色彩、线条和质感

- 参考以大面积低彩度主体、深色四肢和柔和三维阴影建立体积；背景透明，方便进入不同组件。
- 保留柔和 3D 体积与哑光材质。原 GIF 的分辨率和色阶有限，不人为宣称其已高清化；新增插画尽量匹配三视图的干净材质。

### 与组件结合

- 角色只在空状态、加载区、错误恢复和完成反馈中出现；不能常驻遮挡作品。
- 角色脚下或手中道具可自然接入步骤标签、提示条或进度状态，不额外套一层巨大插画卡片。

### 动态节奏与情绪

- 参考 GIF 为 3–6 秒、20fps 的舒缓循环；动作幅度克制，停顿占比高，传达陪伴而非催促。
- 第三版不再在页面中播放 320px GIF。依据三视图重建程序化 3D 模型，独立控制手臂、手掌、身体及道具。
- 共用一个 WebGL 渲染器，最多 30fps、DPR 上限 2；离屏或隐藏时停止，暂停和减少动态模式保留静态姿态。
- 不支持 WebGL 时使用 560px 静态渲染图，文字和状态操作保持可用。
- `prefers-reduced-motion` 下停在有意义的静态姿态，阶段文字仍持续更新。

## 5. 真实体验与功能验证

### 配置与服务

- macOS 私有配置文件存在，权限为 `600`；文字、图片模型字段均已配置。
- 默认 VPN 链路发生 TLS 证书错误；通过项目的 `en0` 安全直连代理后，网关鉴权返回 HTTP 200。
- 隔离端口健康检查：`mode=live`，文字、图片、音乐均报告 available；这只代表健康接口返回值，不能单独证明鉴权、额度、网络和真实生成成功，真实调用结果见下文。
- BGM 虚拟环境与 Stable Audio 服务可启动。

### 自动与真实测试

- `npm test`：50 项通过，覆盖语法、接口、资源、失败、取消、清理与删除。
- 真实文本模型：至少一次成功生成 3 条传播文案与 6 条精华对话；另有多次返回未通过结构校验，表现为间歇性失败。
- 真实下游流程：文案确认成功；2 页漫画、角色/场景整理、图片、配乐提示词、本地 BGM 全部成功；音频约 20 秒。
- 演示浏览器流程：导入故事 → 内容分析 → 文案确认 → 选择形式 → 单图背景 → 海报编辑 → 保存返回 → 生成结果 → 精华对话 → 继续制作漫画，全部可达。

### 已发现问题

1. 内容分析使用随时间上涨的 8%–94% 模拟百分比，不是真实进度。
2. 内容分析失败后返回输入页，只有笼统错误和编号，缺少明确的就地重试动作。
3. 内容分析阶段没有取消/返回入口；图片生成阶段有取消，控制权不一致。
4. 网络或模型结构错误可能让等待时间很长；错误恢复语义不足。
5. 生成任务在 51% 可能停留数分钟，界面缺少“第几页/总页数”等更具体的真实反馈。
6. 后期文字框固定放在每格左上，真实样例中已覆盖人物额头和发际线；原图也存在头部裁切和分格不均的样例，不能把全部问题归因于叠字。
7. 当前没有人脸安全区检测、候选位置评分或分镜外文字区回退。
8. 生成图存在跨页人物呈现漂移风险，连续性 Prompt 已有约束但仍不够稳定。
9. 海报编辑器触发大量 `CanvasTextBaseline: alphabetical` 警告，功能可用但控制台污染严重。
10. 页面存在多个历史版本叠加样式，圆角、阴影、字号和渐变不统一。
11. 加载页面要求“保持本页打开”，但未准确区分可恢复的任务与不可恢复的内容分析请求。

## 6. 设计系统决策

### 色彩

- 品牌蓝 `#1772F6`：主操作、当前步骤、链接、焦点环。
- 蓝色深态 `#125CC4`：悬停与按下。
- 深墨 `#17233D`：主文字和品牌标志。
- 次级文字 `#667085`；弱文字 `#8A94A6`。
- 页面背景 `#F6F7F9`；内容背景 `#FFFFFF`；柔和蓝面 `#F0F6FF`；边框 `#DCE2EA`。
- 主按钮深蓝 `#1264DC`：与品牌蓝同色系，提升白字对比度；角色不再使用黄色围巾，道具统一蓝灰。
- 成功 `#16845B`、警告 `#B76A00`、错误 `#C7352B`，均配合图标或文字使用。

### 字体与层级

- UI/正文：`-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`。
- 故事摘录：`"Songti SC", "STSong", serif`，只在作品内容中使用。
- 字号：12 / 14 / 16 / 18 / 24 / 32；正文至少 14px，移动端输入至少 16px。
- 信息层级通过字号、字重、间距与位置建立，不使用全大写或等宽技术标签装饰。

### 间距、圆角、阴影和栅格

- 4px 基础网格；常用间距 8 / 12 / 16 / 24 / 32 / 48。
- 小控件 6px、输入与按钮 8px、主工作面板 12px、弹窗 16px；不让所有容器共享相同圆角。
- 页面最大宽度 1180px；主流程内容采用 8/4 或 7/5 栅格，结果页作品区域优先。
- 静态内容面默认无阴影；仅浮层和拖动画布使用两级柔和阴影。

### 组件和状态

- 每屏最多一个主按钮；次按钮使用浅灰或描边；危险操作远离主流程并使用红色语义。
- 输入框始终有可见标签；占位符只举例，错误紧邻字段并给出恢复方式。
- 步骤导航明确当前、完成和未开始，允许返回已完成步骤并保留结果。
- 空状态给出下一步；成功状态说明产物与后续动作；失败状态说明原因范围、已保留内容和重试入口。
- 模型名称、Prompt、评分、内部状态值默认隐藏；服务是否可用用普通用户语言表达。

## 8. 漫画文字安全区方案（确认后实施）

1. 生图 Prompt：固定角色圣经；禁止极端近景、头部出框、脸部重叠；头部四周预留空间；明确每格至少一个自然文字留白区。
2. 后期布局：文字按格独立计算，先测量换行、字号与框尺寸，再选择位置。
3. 候选位置：左上、右上、左下、右下、顶部通栏、底部通栏；按人脸/头部安全区、关键动作区和画面对比度评分。
4. 人脸安全区：优先使用浏览器端轻量 FaceDetector（可用时）或离线检测结果；安全框在检测框四周扩展 18%–24%。
5. 回退：所有候选位置都冲突时，在该分镜下方增加独立旁白带，不覆盖图片；对话气泡尾巴指向角色但气泡本身避开头脸。
6. 文本适配：限制最大行宽和行数，逐级缩小到可读下限；仍放不下时扩高外置旁白带，不截断文字。
7. 验收：自动几何碰撞测试 + 实际截图人工复核；覆盖近景、多人、长旁白、连续人物与移动端预览。

## 11. 第三版：边缘质量与独立状态动作

### 用户指出的问题与修正

用户指出 GIF 边缘锯齿明显，首次进入、生成完成、导出完成动作相同。代码核实三个状态确实共用 greeting。旧 GIF 只有 320px，不能以改格式或模糊处理声称恢复高清。

本轮改用参考三视图的程序化 3D 重建，不是官方模型，也不是修复原 GIF。保留白色头身、尖耳、大黑鼻和细黑四肢；耳朵与身体使用连续网格；手臂根据道具位置计算，避免手掌悬空。原文件全部保留。

### 独立动作

- 首次进入：右手抬起、手掌轻挥、落回，身体小幅倾斜。
- 生成完成：双手整理作品夹，再点头；不挥手。
- 生成失败：低头检查单页纸稿，随后抬手示意继续；不哭泣。
- 导出完成：向前递出作品夹，另一只手随后挥手。
- 理解故事：捧书、翻页。
- 设计分镜：手跟随分镜纸张整理位置。
- 生成画面：手持铅笔在画板前移动。
- 创作配乐：戴耳机、轻触耳罩并点头。

这些是实时网格/关节/道具动画，不是生成视频或多张静态图淡入淡出。下方三联 AI 插画仅保留作之前的姿态参考。

### 状态互斥矩阵

| 场景 | 角色动作 | 道具/成果 | 触发与结束 |
|---|---|---|---|
| 静态 Logo | 近景抱蓝色钩形 | 蓝色钩形，无成果卡 | 静态，不表示任务正在执行；完整持竿用于场景而非 App 图标 |
| 首次进入/空状态 | 持竿招呼，短暂回应后停稳 | 鱼竿与垂线，无成果卡 | 首次显示时短动作；不与等待采用同一循环 |
| 理解故事 | 阅读、轻微翻页 | 故事本 | 只有真实可观测的独立阶段才展示；否则与准备文案合并 |
| 传播文案生成等待 | 观察钓线、轻调鱼竿、安静停顿 | 垂线伸出画面下方，无成果卡 | 真实请求进行中；不得按时间钓出成果 |
| 传播文案生成完成 | 提竿带起卡片，接住并停下 | 蓝色夹扣连接故事钩子卡 | 响应成功、校验通过且有可展示文案后，单次播放；不阻塞结果展示和操作 |

| 失败 | 停止当前动作、检查纸稿、示意重试 | 无新成果 | 按真实错误显示恢复操作，不继续等待或演成功 |
| 取消 | 收住当前动作，停在静态姿态 | 无新成果 | 等待/完成动效停止；迟到成功不再触发提卡 |
| 导出文件生成完成 | 递出作品夹 | 作品夹，不是钩子卡 | 实际文件已生成后播放一次；不声称用户本地已保存 |

### 防冲突约束

1. 同一任务同一时间仅有一个主状态；等待、成功、失败、取消互斥。角色动作由业务状态驱动，绝不反过来决定业务完成。
2. 分析与文案若是一体请求、没有独立阶段事件，使用“正在理解故事并准备传播文案”搭配垂钓等待；不要为了展示两个动作制造虚构阶段。
3. 完成事件按任务/请求标识去重；轮询重复返回、页面重绘不重复播放提卡。取消或切换作品后，旧任务不能触发新页面的成功动作。
4. 文案先可用，动画后表达反馈；用户可立即选择、返回或修改，动画不是操作门槛。
5. 暂停和减少动态模式使用对应静态姿态，仍显示完整结果；不可用渲染环境有清晰静态回退。
6. 角色不进入导出的漫画、故事卡或海报画布，不与创作者内容争夺注意力。
