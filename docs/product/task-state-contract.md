# 任务状态契约：现状与实施约束

> 最新范围（优先于历史计划）：只修改页面文案、UI 和动效。不改漫画 Prompt、漫画排版及核心功能。当前基线 0501993 已撤回聊天截图/视频；相关旧条目不实施、不恢复。FLOW/COMIC 等核心修复项退出本轮。第八轮视觉已批准。

2026-09-14。依据：本地 app.js、server.mjs、poster-editor.js。本文是代码核查后的实施规格，不是全部异常路径已实测通过的声明。4173 正在运行的接口与这些源码存在差异，正式运行前必须对齐服务版本。

## 1. 现有流程不是强制串行流水线

输入 → 分析与传播文案（一体请求）→ 文案检查确认 → 选择形式。

- 漫画分支：选画风 → 确认生成 → 图片任务；勾选配乐时，与配乐任务并行 → 复核/导出。
- 单图分支：选背景 → 海报编辑、保存 → 返回确认生成 → 素材任务 → 复核/导出。
- 聊天截图/聊天视频在结果页使用分析返回的精华对话，属于现有独立导出，不应新增为强制步骤。

不能把海报编辑强制放到漫画与 BGM 之后，也不能用等待动画假装图片和配乐必定前后相继。

## 2. 请求与业务完成条件

| 业务 | 现有入口 | 可观测状态/成功依据 | 现有问题及正式接入约束 |
|---|---|---|---|
| 分析与文案 | POST /api/projects/analyze；analyze | 单个请求，返回 story_profile、candidates 等；无逐阶段事件 | updateAnalysisProgress 按时间编造阶段和百分比。改为合并等待；返回结构检查通过、文案可显示才触发一次提卡 |
| 文案确认 | POST /api/projects/:id/select-hook；confirmHook | selected_hook_profile.validation_status = passed 才进入形式页 | 20～300 个非空白字符；失败留在编辑页。检查失败不能演素材成功 |
| 开始素材生成 | POST /api/projects/:id/generate；startGeneration | 202 返回任务 ID，随后 GET /api/tasks/:id | 未取得 ID 前也要防重复提交；轮询需绑定任务 ID，不允许旧响应覆盖新任务 |
| 图片准备 | visual_context 子任务 | queued/running/succeeded/failed | 标签是整理角色和场景，不能断言存在独立实时“设计分镜”进度；若无相应事件，合并显示准备画面 |
| 图片生成 | material 子任务、image_assets[].status | 图片状态及可用图片地址 | 只展示确已完成页数，不用 task.progress 冒充真实耗时完成度 |
| 配乐准备/生成 | music_prompt、music 子任务 | 独立子任务状态、audio_url | 与图片并行。未勾选不展示；仅有音频且子任务成功才称完成 |
| 编辑保存 | poster-editor.js 保存事件 | 序列化状态写入浏览器成功后 savedForReturn=true | 是本浏览器定稿保存，不是云端永久保存；存储空间不足时不能显示已保存 |
| 导出包准备 | exportPackage；PATCH 项目信息、GET export、POST final-images | 最终图片提交成功后才展示下载链接 | 链接可见不代表 ZIP 已被下载或打开。与业务生成成功分开 |
| 本地视频合成 | buildVideoPreview / buildChatVideo | MediaRecorder 结束并取得有效 Blob | 基于真实合成帧/时长的比例可以保留；不是模型生成百分比。合成完成才提供下载 |

## 3. 素材任务终态

| task.status | 源码行为 | 用户界面与角色 |
|---|---|---|
| queued | 已建立任务、尚未处理 | 等待开始，不展示成果 |
| running | 仍有排队/运行的子任务 | 一个主动作；图片和配乐进度分别文字呈现，不叠两个角色 |
| succeeded | 图片成功，且没有失败的配乐任务 | 素材完成，整理作品夹一次；不是传播文案提卡 |
| partially_failed | 图片成功、配乐失败 | 图片可用＋配乐重试；不能显示全部成功，也不隐藏图片 |
| failed | 图片失败，可能仍有已完成素材 | 就地恢复，重试失败项；保留已有结果但不假称所有结果可导出 |
| canceled | 取消接口标记并中止控制器 | 停止动作，显示取消；绝不继续提卡 |

finalizeTask 的 progress 使用子任务数量加权并封顶，不是准确的工作量/时间进度，正式主界面不使用其百分比。

并行动作选择规则：图片准备/生成未完成时优先对应画面动作；图片完成而配乐仍运行时切换听音动作；配乐先完成则继续画面动作。失败子任务立即说明，但仍运行的任务不被假终止。所有必需子任务终止后按上表显示终态。

## 4. 返回、取消、重试与迟到响应

- 当前 showPage 只切换页面，不中断请求。pollTask 成功时会主动打开结果页；用户返回输入后仍可能被带走。实施时以用户当前查看意图决定是否自动跳转，否则就地提示完成。
- analyze 没有 AbortController、请求代次或取消端点；导航返回仍可能被完成响应带到文案页。修复需客户端请求代次校验/中止等待；不得声称供应商计算已经取消。
- 素材取消 POST /api/tasks/:id/cancel 仅接受 queued/running；服务端 abort 控制器并将未完成子任务标记 canceled。HTTP 中止不保证上游供应商已停止计费/计算。
- 取消成功只清除定时器，正在飞行的旧轮询仍可能回来。前端必须比较 projectId、taskId、请求代次和取消标记后再应用结果。
- 重试仅接受 failed/partially_failed；startTask(task,true) 复用任务 ID、增加 attempt、跳过已成功图片。取消任务不属于现有 retry 可接受集合，应返回设置重新发起，不显示无效“重试失败部分”。
- 状态读取失败不是生成失败：保留当前状态，提供重新读取/返回；后台轮询退避，不反复弹错误。
- 完成动作去重键至少为 projectId + taskId/requestId + 业务完成类型；重绘、重复轮询、离屏返回不重复播放。结果先显示，动画不延迟操作。

## 5. 结果保留与失效边界

| 数据 | 当前代码确认 | 修改要求 |
|---|---|---|
| 正文 | saveState 明确清空持久化 body；在当前内存/输入框内保留 | 不说刷新后正文仍在；返回与刷新必须区分 |
| 分析与未确认草稿 | 持久化清空 analysis 和 hookDraft；restoreProject 重新取分析并选候选 | 刷新可能丢未确认改写，不能用“自动保存”笼统承诺；至少离开前准确提示 |
| 已确认文案 | selectedHook 持久化，项目恢复可补取 | 编辑时置空 selectedHook；下游可用性必须同步失效，禁止旧任务作为新文案结果 |
| 海报 | 主页面在 session 保留预览，localStorage 去掉预览；编辑器保存路径又写入完整状态 | 两条保存路径需统一验证，不保证跨标签恢复完全一致 |
| 任务/历史 | 浏览器保存任务摘要及最后四条历史，恢复依赖服务端 GET | 服务端过期/缺失应明确提示；不能静默回输入假装首次使用 |
| 修改上游 | analyze 成功清空 task；confirmHook 清空 posterDesign，但其他下游状态不全清 | 用作品/确认文案版本绑定结果。旧素材保留为旧版，不混作当前稿 |

实施验收：取消后迟到成功、切换作品后旧轮询、两次分析竞态、刷新草稿、服务端任务过期、图片成功配乐失败、同任务重试、导出失败均需测试。上述为已明确的实现契约，不再留为待用户回答的问题。
